# ドメインを引き継ぐか、新しく取り直すか

引き継ぎ先と相談するための判断材料。
決まったあとの作業手順は、A案なら §5、B案なら `docs/DOMAIN-MIGRATION.md`。

最終更新: 2026-08-31

---

## 結論（こちらからのおすすめ）

**A案：`www.my-japan-matcha.com` をそのまま引き継ぐ。**

どちらを選んでも引き渡しが必要なものが5つ残る（§1）。ドメインだけ切り離しても
手離れは良くならず、一方で既存のリンク・シェア画像・検索順位はすべて失われる。

ただし **MATCHAの名前から離れたい**のであれば、B案には十分な理由がある。

---

## 1. どちらを選んでも引き渡しが必要なもの

ここが判断でいちばん大事な点。ドメインの選択に関係なく、次の5つは引き渡すか
作り直すことになる。

| なに | なぜ |
|---|---|
| **Supabase** | DB・ログイン・写真の置き場。**作り直しは不可能**。作り直すと利用者のアカウントも、投稿された旅も写真もすべて消える |
| Google アナリティクス | プロパティは個人のGoogleアカウントに紐づいている。ドメインを変えなくても引き渡しが必要 |
| Google 認証 | GoogleログインのOAuthクライアント。Google Cloud のプロジェクトごと引き渡す |
| Mapbox | 地図のアクセストークン。先方のアカウントで発行し直すのが安全 |
| Meta ピクセル | 広告の計測ID。先方のIDに差し替え |

### よくある誤解

**ドメインを変えてもアナリティクスとGoogle認証が使えなくなるわけではない。**

- アナリティクス … データストリームのURLを足すだけ。過去のデータも消えない
- Google認証 … 「承認済みのJavaScript生成元」に新しいドメインを足すだけ。
  認証の戻り先は Supabase 側のURL（`https://<ref>.supabase.co/auth/v1/callback`）なので変わらない

つまりこの2つは **A案・B案どちらでも引き渡しが要る**もので、選択の決め手にはならない。

---

## 2. それぞれ何をすることになるか

### A案：いまのドメインを引き継ぐ

- **コードは1行も変えない。** デプロイし直す必要もない
- すでにSNSに貼られた旅のリンクが**生き続ける**
- 利用者が投稿したシェア画像に焼き込まれたドメイン文字が**有効なまま**
- 検索順位を**そのまま引き継げる**
- MATCHA記事に「My Japanに保存」を埋める作業に**すぐ着手できる**
- ✗ お名前.comのアカウントの引き渡しが必要（支払い方法・二段階認証の付け替え）
- ✗ サービス名がMATCHAブランドに紐づいたままになる

### B案：新しいドメインを取る

- **前任者との縁が完全に切れる。** アカウントの引き渡しが1つ減る
- サービス名を**自由に決められる**
- ✗ すでに貼られたリンクが**すべて切れる**（旧ドメインを保持して転送しない限り）
- ✗ 配布済みのシェア画像に旧ドメインの文字が残る。**これは直せない**
- ✗ 検索順位がリセット（転送で緩和は可能）
- ✗ MATCHA記事への埋め込みは**ドメインが決まるまで着手できない**
- ✗ 設定作業が1〜2時間ぶん増える

> B案のコード側の作業は **1行に集約済み**（`lib/site.ts` の `SITE_HOST`）。
> 仮のドメインでビルドを通して確認してある。画面の外でやることは
> `docs/DOMAIN-MIGRATION.md`。

## 3. 違いが出るところ

| | A案 ／ 引き継ぐ | B案 ／ 取り直す |
|---|---|---|
| コードの変更 | ◎ なし | △ 1行＋設定（1〜2時間） |
| 既存の共有リンク | ◎ 生きる | △ 切れる（転送を張れば維持） |
| 配布済みシェア画像 | ◎ 有効 | △ 旧ドメイン表記が残る（**修正不能**） |
| 検索順位 | ◎ 引き継ぐ | △ リセット（転送で緩和） |
| MATCHA記事への導線 | ◎ すぐ着手できる | △ ドメイン確定まで待ち |
| アナリティクス | — 引き渡しが必要 | — 引き渡し＋ストリーム追加 |
| Google 認証 | — 引き渡しが必要 | — 引き渡し＋生成元の追加 |
| Supabase | — 引き渡しが必要（必須） | — 引き渡しが必要（必須） |
| 費用 | ◎ 更新料のみ（年1,000〜2,000円程度） | △ 新規取得＋旧ドメインの保持料 |
| 命名の自由 | △ MATCHAブランドに固定 | ◎ 自由に決められる |

## 4. この3つに答えれば決まる

**① サービス名を「My Japan（MATCHA運営）」のまま続けるか？**
続ける → **A案**（ブランドを変えないなら、ドメインを変える理由が無い）
変える → **B案**（名前を変えるなら、ドメインも一緒に変えるのが自然）

**② すでに利用者がSNSに貼ったリンクや投稿画像を、生かしたいか？**
生かしたい → **A案**。B案では、投稿画像に焼き込まれたドメイン文字は
**あとから直す方法がない**。リンクのほうは旧ドメインを1年ほど保持して
転送すれば維持できる。

**③ お名前.comのアカウントを引き受けられるか？**
引き受けられる → **A案**（その日のうちに終わる）
社内規定などで難しい → **B案**（他社レジストラへの移管という手もあるが5〜7日）

---

## 5. A案の手順（お名前.comのアカウントごと引き渡す）

ドメインはどこにも動かさないので、**サイトが止まらない**。

1. **アカウントの連絡先メールを変更する** — お名前.com Navi → 登録情報
2. **支払い方法を会社のカードに差し替える** — ここが個人カードのままだと、
   更新に失敗してドメインが失効する
3. **二段階認証・SMS認証の連絡先を変更する** — 電話番号が前任者のままだと、
   パスワードを知っていてもログインできない
4. **パスワードを変更し、実際にログインできることを一緒に確認する**

### 他社レジストラへ移す場合（5〜7日）

Whois情報公開代行の解除 → 移管ロック解除 → AuthCode発行 → 先方が申請 → 双方承認。

⚠️ **登録者情報を変更した直後は60日間移管できない。**
移管を先に、登録者情報の変更を後に。

### 現在のDNS（実測）


---

## 6. どちらでも当てはまる提案

仮にB案を選ぶ場合でも、**旧ドメインを1年だけ保持して新ドメインへ301転送する**
ことをすすめる。年間1,000〜2,000円程度で、既存のリンクと検索順位を引き継げる。
その1年のあいだにMATCHA記事側の導線を新ドメインに入れ替えれば、失うものは
ほとんどない。
