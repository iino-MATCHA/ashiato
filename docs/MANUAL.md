# My Japan — 使い方（利用者・運営・道具）

アプリの画面の使い方（§1〜3）、運営の日常作業（§4）、
記事データを作り直す道具（§5）をまとめてある。
引き継ぎの段取りそのものは `docs/HANDOVER.md`。

最終更新: 2026-08-29（印刷版の販売取りやめを反映）

---

## 1. 利用者の画面（5言語対応: en / ja / ko / zh-Hans / zh-Hant）

言語はブラウザの言語から自動判定。切替UIは意図的に置いていない。

### ホーム `/map`
- 日本地図。訪れた県が塗られ、県をタップすると下からカードが出る
- 県カードの並びは「あなたの記録 → みんなの旅 → 県の紹介 → 行くなら」。
  「行くなら」の札（若松城・三春滝桜など）を押すと、その場所の概要と
  MATCHAの写真のポップアップ。下の緑のボタンでMATCHA本体の記事へ
- 「あなたの旅」一覧のいちばん上のカードから、**写真を選ぶだけで旅を作れる**
  （EXIFの撮影日時と位置から自動で立ち寄り先を組む。60枚まで）

### 旅 `/trip/[id]`
- Mapbox の日本地図に写真ピンとルート。カードの横送りと地図が連動
- 右上の設定アイコンから編集（題・期間・公開/非公開）。
  その下の写真アイコンで、**既存の旅に写真を追加**（日付どおりの位置に入る）
- 共有ボタン → シェアカード（暗い和紙に日本地図＋写真。保存/Stories/X）

### ジャーナル `/trip/[id]/bind` → `/trip/[id]/book`
- 見本（本のプレビュー）をめくると、**開いているページの編集欄だけ**が
  下に出る。枚数（1〜6）とその中身を一覧のタップで決める。
  表紙は表紙が見えているときだけ編集できる。写真のドラッグも効く
- 「この本のための写真」から、旅には出さない写真だけを足せる
- 「PDFにする」→ `/trip/[id]/book` で台割を並べて **Export PDF**。
  無料で何度でも取り出せる
- 旅ごとのPDFは `/journals`（プロフィール → 手元のジャーナル）にも並ぶ
- **印刷版の販売は 2026-08 に取りやめた。** かご・購入手続き・注文履歴・
  Stripe はコードごと削除してある

### 御朱印 `/goshuin`
- 47都道府県、1県1つ。旅で訪れると埋まる
- 「御朱印バッジとは？」→ 本物の御朱印とは別物であることの説明
  （初回は自動で開く）

### 診断 `/quiz`
- 12問に答えると、合う都道府県を1〜3件すすめる。訪問済みの県は出さない
- 結果ページから旅の計画（アフィリエイトリンク）や県のMATCHA記事へ

### 発見 `/explore`
- 公開の旅と人気の観光エリア。**未ログインでも全部見られる**
  （保存が要る操作だけ、その場でログインを促す）

## 3. 管理画面 `/admin`（日本語のみ・管理者のみ）

権限は3段階: **閲覧のみ / 編集 / 全権**。全権の出どころは
`iino@matcha-jp.com`（変え方は HANDOVER §1-2）。

| タブ | できること |
|---|---|
| 全国 | 利用状況の全体。インバウンド/国内の2分割、月次の推移 |
| 都道府県 | 県ごとの利用状況。県を開くと、その県の移動手段の内訳も出る |
| 市区町村 | チェックインの多い場所の一覧とヒートマップ |
| 広告 | スポンサーカードの管理（§4-2） |
| 運営 | 管理者の付け外し（メールアドレスで）。直近の登録と旅 |

## 4. 運営の日常作業

### 4-1. スポンサーカード（広告）を出す
1. /admin → Sponsors → 画像を取り込み（推奨 1600×1000px以上・16:10）
2. 会社名（内部用）・表示名・タイトル・リンク先URL・表示順を入れて保存
3. /explore の「注目の旅」に、旅3件ごとに1枚差し込まれる
4. 止めるときは「非表示」。消さなくても非表示にすれば出ない

※「PR」表記なしはオーナー判断（法務確認を推奨。HANDOVER §3）
※広告はいまのアプリの収益の軸。提携先を増やすときもここから足す

### 4-2. 管理者を増やす・外す
1. /admin → 運営 → 権限を選ぶ → メールアドレスを入れて追加
2. **相手が先にアプリへ登録している必要がある**（未登録だと「見つかりません」）
3. 外すのは一覧の「外す」を2度押し。自分と持ち主は外せない

### 4-3. 県の紹介文・記事を直す
- 県の紹介文: `prefecture_texts` 表（47県×5言語）。SQL Editor で直接
  update してよい。行が無い言語は日→英の順で代替が出る
- 記事: `matcha_articles` 表。1行消せばその記事は出なくなる。
  `place` が null の記事は県カードの並びに出ない（ポップアップの元データは残る）

## 5. 記事データを作り直す道具（`scripts/`）

MATCHAの記事を47都道府県×5言語で取り込み、行き先の札（place）と
概要文を付ける道具。**全部読み取り専用で、DBへは触らない**
（出力されたSQLファイルを人が貼る）。

```bash
# ① MATCHAから県ごとに記事を集める（1〜2時間・Wikipediaにもアクセス）
node scripts/import-matcha-articles.mjs --by-prefecture --per-prefecture 3 --sql

# ② 場所の特定と概要文の差し替え（supabase/seed/articles/ に50件ずつのSQLを出す）
node scripts/enrich-article-spots.mjs
#    --lang jp --verbose --dry-run  … 日本語だけ・1件ずつ表示・SQLを書かない

# ③ できたSQLの目視チェック
node scripts/check-article-quality.mjs jp 7   # 福島県の日本語ぶんを表示
node scripts/check-article-quality.mjs jp     # 全県の1行まとめ

# ④ 貼る: supabase/seed/articles/00_reset.sql → jp_1of4 … tw_3of3 の順
```

仕組みの要点:
- 県の判定はMATCHA記事のパンくずだけを信じる（ヘッダのリンクは全記事共通なので使わない）
- 場所の札は「Wikipediaで座標を持つページ」と確かめられたものだけ。
  駅・ホテル・学校・企業・自治体・災害のページは弾く
- 一覧・季節ものの記事は本文をWikipediaの導入節（その場所の概要）に
  差し替える。**写真はどの場合もMATCHAのまま**
- Wikipediaの結果は `.masters/wiki-cache.json` に控えを持つ。
  選び方を変えたときはこのファイルを消してから回す

## 6. 困ったときに見る場所

| 症状 | 見る場所 |
|---|---|
| 画面にデータが出ない | ブラウザのコンソール → Supabase の RLS ではなくクライアント側をまず疑う（CLAUDE.md） |
| 記事のポップアップが出ない | `matcha_articles` に行があるか、`place` が入っているか |
| 地図が真っ白 | Vercel の `EXPO_PUBLIC_MAPBOX_TOKEN` が生きているか |
| デプロイが反映されない | Vercel のビルドログ。mainに入っているかを確認 |
